# ETL-3 Knowledge Base Migration (`dopams_cctns_v2`)

## 1. Purpose

Parallel enhanced ETL-3 database:

| Database | Role |
|---|---|
| `cctns_v1` / `cctns-v2` | READ ONLY sources |
| `dev-2` | READ ONLY one-time KB migration source |
| `dopams_cctns` | READ ONLY baseline / reference (unchanged) |
| `dopams_cctns_v2` | Sole write target for this phase |

`dopams_cctns_v2` holds:

1. Merged CCTNS V1+V2 unified data (cloned from baseline `dopams_cctns`)
2. Enrichment tables
3. Local Knowledge Base under schema `kb`

## 2. Schema separation

```
dopams_cctns_v2
├── public   → unified + enrichment + ETL control tables
└── kb       → drug_categories, drug_ignore_list, geo_reference, geo_countries
```

Rules enforced:

- No KB tables in `public`
- No public views/aliases exposing KB
- Application-facing data stays in `public`

## 3. Source → target mapping

| Source (`dev-2.public`) | Target (`dopams_cctns_v2.kb`) |
|---|---|
| `drug_categories` | `kb.drug_categories` |
| `drug_ignore_list` | `kb.drug_ignore_list` |
| `geo_reference` | `kb.geo_reference` |
| `geo_countries` | `kb.geo_countries` |

Columns preserved from source (including useful extras such as `category_group`, `raw_name_clean`, `timezone`). No invented columns.

**Intentional structural differences**

| Item | Difference |
|---|---|
| Schema | `kb` instead of `public` |
| Identity | `GENERATED BY DEFAULT AS IDENTITY` (same insertability of explicit ids) |
| Duplicate uniques on `drug_categories.raw_name` | Collapsed to one `UNIQUE(raw_name)` (source had two identical unique constraints) |
| Redundant geo trgm indexes | One GIN index per geo text column (source had overlapping duplicates) |

## 5. Indexes / pg_trgm

- Extension: `CREATE EXTENSION IF NOT EXISTS pg_trgm` on `dopams_cctns_v2`
- Drug lookup index: `kb.drug_categories USING gin (raw_name gin_trgm_ops)`
- Geo trgm indexes on state/district/sub_district/village and country/state

Historical drug similarity query:

```sql
SELECT standard_name, similarity(raw_name, :q) AS sim
FROM kb.drug_categories
WHERE is_verified = true
  AND similarity(raw_name, :q) >= 0.35
ORDER BY sim DESC
LIMIT 1;
```

## 6. Lookup semantics (preserved)

### Drug name resolution

1. Exact lowercase match on `raw_name`
2. Substring (KB key in raw, then raw in KB key when `len(raw) >= 4`)
3. `pg_trgm` similarity ≥ **0.35**, only `is_verified = true`
4. Else keep raw / leave unresolved (no invented canonical name)

### Ignore list

- Exact match on resolved `primary_drug_name` (lower/trim)
- Never substring-matched against raw text (historical safety rule)

### `category_group` vs enrichment `drug_category`

`kb.drug_categories.category_group` is **not** the Cannabis/Opioid/… label.
Those labels come from `etl3/enrichment/rules.py` → `resolve_drug_category`.

### Geography / domicile

- `kb.geo_reference` / `kb.geo_countries` feed address confirmation
- Deterministic domicile rules unchanged (India+Telangana → native state, etc.)
- Stored CCTNS domicile / source values remain authoritative (`source_column` wins)

### Gender

No gender KB table. Existing person/`gender_source='api'` behavior unchanged.

## 7. Static `drug_mappings.json` precedence

File kept at `etl3/enrichment/drug_mappings.json`.

Deterministic rule:

1. `kb.drug_categories` wins on shared raw keys
2. Static entries absent from KB are used as extras
3. Conflicts are **not** silently overwritten by the static file

Observed on migration validation:

- KB rows: 379
- Static rows: larger alias file
- Conflicts: 22 (KB wins)
- Static-only extras: 278 (merged into runtime lookup)

## 8. Runtime independence from `dev-2`

After migration:

- Enrichment loads drugs/geo from `kb.*` on the unified connection
- No runtime connection to `dev-2`
- One-time loader: `etl3/migrations/migrate_kb_from_dev2.py` (read-only source session)

## 9. Ollama

Runtime endpoint and model come **only** from environment / `etl3/config/.env`.
There is no hardcoded host or model fallback in ETL-3 code.

| Setting | Source |
|---|---|
| Endpoint | `OLLAMA_BASE_URL` (alias: `OLLAMA_HOST`) |
| Model | `OLLAMA_MODEL` (alias: `LLM_MODEL_EXTRACTION`) |
| Gate | `ETL3_AI_ENABLED=1` requires both URL and model |

Historical lab note (not runtime config): an earlier verification used
`http://192.168.102.21:11434` with `qwen2.5:32b-instruct-q4_K_M` via `/api/tags`.
Production `.env` must set the current confirmed values explicitly.

Controlled smoke test extracted `dry ganja` / `2 kg` from a short seizure sentence without inventing extra drugs.

AI safety:

- Validate JSON before persist
- Empty / invalid / timeout do not overwrite good rows
- AI does not replace deterministic CCTNS source values
- Missing facts stay NULL

Default `.env` keeps `ETL3_AI_ENABLED=0` until a bounded backfill is intentionally enabled (`ETL3_AI_LIMIT`).

## 11. Bootstrap note

`dopams_cctns_v2` started empty. An early bootstrap cloned baseline `dopams_cctns` into it so enrichment had unified rows to run against. That was **beyond the KB-only request** and was reversed:

- `public` / `be_read` / `dopams_app` dropped and rebuilt empty via migrations `001`–`014`
- `kb.*` left intact (379 / 197 / 676108 / 10520)
- Baseline `dopams_cctns` was never modified

Fresh load path: run ETL-3 phase-3/4 (or daily incremental) into `dopams_cctns_v2`, then enrichment with local `kb.*` + optional Ollama.

## 12. Known limitations

- Full AI enrichment backfill is gated; enable with `ETL3_AI_ENABLED=1` and prefer `ETL3_AI_LIMIT` for staged runs
- Loading full `geo_reference` into memory for address confirmation is heavy (~676k rows)
- 22 static/KB standard-name conflicts keep KB values; review list via `compare_static_mappings(conn)`
- Production V1/V2 schedules and baseline `dopams_cctns` are intentionally unchanged (no cutover)

## 13. Enrichment backfill + idempotency

Ran `run_enrichment` twice on `dopams_cctns_v2` with `ETL3_AI_ENABLED=0` (deterministic + local KB only).

| Run | Notable |
|---|---|
| First | Accused fill-in (V1 rows inserted), small property/drug/chargesheet inserts; AI `disabled` |
| Second | All families `inserted=0` / `updated=0` (unchanged counts only) |

Follow-up migration: `014_accused_status_width.sql` widens `accused_enrichment.status` to `VARCHAR(255)` so full CCTNS status text is preserved.
