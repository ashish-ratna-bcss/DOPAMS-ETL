None of these have been mitigated in code yet — this is a planning document.

## Summary

- **Resolved this pass:** R10 (full V2 provenance confirmed), R13 (documented as a known exception, not a blocker).
- **Highest-priority open risk:** R8/R5 — DOPAMS BE's location and database target remain unknown and block real cutover planning; this is a non-technical, investigation-only blocker, not an ETL-3 engineering task.
- **Highest-priority technical design risk:** R11 — V1's incremental-detection mechanism is structurally asymmetric with V2's and must be built, tested, and verified against a live run before being trusted, not assumed to work the same way.
- **Hardest invariant to protect in implementation:** R12 — enforced at the database grant level, not just in application code, per the task's explicit instruction.
