# ETL-3 Implementation Phases

Each phase is independently verifiable — it produces something that can be checked against live V1/V2 data before the next phase starts, and no phase requires writing to `cctns_v1` or `cctns-v2`. Phases 0–2 are prerequisites that exist outside ETL-3's own code. See `ETL3_MERGER_IMPLEMENTATION_PLAN.md` for the full reasoning behind each design decision referenced here, and `ETL3_UNIFIED_SCHEMA.sql` for the exact DDL.

| Phase | Scope | Depends on | Verification before moving on | Status |
|---|---|---|---|---|
| **0** | V1/V2 source ETL fixes (run-lock, known-gap classification, checkpoint/half-open/arrests-uniqueness) | — | Already live-verified: run 56 `loaded_with_known_gaps`, V2 arrest duplicates = 0 | **Done** |
| **0.5** | Locate and inspect the actual DOPAMS BE application; confirm its current database target, read vs. write patterns | — | A real repository/deployment is found and its `DATABASE_URL`/connection config is read (read-only) | **Not started — recommended before any further phase**, per R8 in the risk register |
| **1** | Stand up `dopams_unified` database, empty, with the full `ETL3_UNIFIED_SCHEMA.sql` DDL applied | Phase 0 | `\dt` shows all 6 table families present; no FK errors on creation | Not started |
| **2** | Create ETL-3's own database roles/credentials: `etl3_v1_reader` (SELECT-only on `cctns_v1`), `etl3_v2_reader` (SELECT-only on `cctns-v2`), `etl3_writer` (full DML on `dopams_unified` only) | Phase 1 | `information_schema.role_table_grants` for each role shows exactly the expected privileges and nothing else — specifically, zero INSERT/UPDATE/DELETE grants on any `cctns_v1`/`cctns-v2` table | Not started |
| **3** | Build the V2 source-observation ingester: read `crimes`/`accused`/`persons`/etc. via `etl_run_id`, write to the matching `*_source` table | Phase 2 | Row count in `crimes_source` for `source_system='V2'` equals the count of distinct `(crime_id, etl_run_id)` pairs actually present in V2's `crimes` table for the runs processed so far | Not started |
| **4** | Build the V1 source-observation ingester: the two-table join (`cctns_v1_etl_row_action` → business table), write to the matching `*_source` table | Phase 2 | Row count in `crimes_source` for `source_system='V1'` matches the number of `cctns_v1_etl_row_action` rows for `table_name='cctns_fir'` across the runs processed | Not started |
| **5** | Build current-state computation for `crimes_unified` only (simplest entity — no identity resolution needed) | Phase 3+4 for crimes | `crimes_unified` row count == 7,305 (V1) + 9,535 (V2) == 16,840 exactly, zero `(source_system, source_record_id)` collisions | Not started |
| **6** | Extend current-state computation to `persons_unified` (plain union, still no linking) | Phase 5 pattern proven | `persons_unified` row count == V1 `accused_details` person_code count + V2 `persons` count, exactly | Not started |
| **7** | Extend to `accused_unified`/`arrests_unified`, including the V1 stale-duplicate collapse algorithm and NULL-`person_id` handling for V2 | Phase 6 | Spot-check the known 69-row V1 churn outlier collapses to exactly 1 current + 68 `change_log` rows; confirm all 78 V2 NULL-`person_id` rows load with `unlinked_person_flag=TRUE`, none rejected | Not started |
| **8** | Extend to the remaining entity families: `seizures`, `chargesheets`, `properties`, `fsl`, `disposal`, `interrogation`, `hierarchy` | Phase 7 pattern proven | Row counts match source counts per `ETL3_SOURCE_COMPATIBILITY_MATRIX.md`, per entity | Not started |
| **9** | Build `change_log` population + `bulk_event_exclusions`, seeded with the 2026-08-24 V2 event | Phase 7/8 | Re-process a window spanning 2026-08-24 and confirm zero `change_log` rows are written with `change_classification='business_change'` for that date — all fall under `administrative_bulk_excluded` | Not started |
| **10** | Build `identity_links` candidate generation (re-run the ~300–330-pair matching batch against current data first) | Phase 6 | All generated rows have `status='candidate'`; zero rows anywhere have `status='confirmed'` without a `reviewed_by` value set by an actual human action | Not started |
| **11** | Build `source_gap_ledger` seeding (V1's 180-row ledger, V2's FK-retry/address/unlinked-accused populations) | Phase 1 (no dependency on 3–10) | Ledger counts match source counts exactly at seed time | Not started |
| **12** | Build `consolidation_cursor` + the floor-before-commit transaction pattern; wire up cursor advancement only after Families 1–3 fully commit for a given source run | Phases 3/4 | Kill the ETL-3 process mid-run (test environment only) and confirm the cursor did not advance and the next run fully reprocesses with no duplicate `change_log` rows | Not started |
| **13** | Build the reconciliation job (`reconciliation_run_log`, per-table delta tracking, cursor monotonicity check) | Phase 12 | Run it against a fully-caught-up state and confirm zero deltas and zero alerts | Not started |
| **14** | Monitoring/alerting wiring (staleness, gap-ledger growth, NULL-person_id rate drift) | Phase 13 | Manually trigger each alert condition in a test environment and confirm it fires | Not started |
| **15** | Full incremental run, end-to-end, against live (but still read-only-sourced) data for a sustained period | Phases 3–14 | Reconciliation shows zero unexplained deltas across a full day's worth of both sources' normal cadence (V1 ~daily, V2 ~4x/day) | Not started |
| **16** | DOPAMS BE cutover (net-new surfaces first, per `MERGER_REVALIDATION.md` §22) | Phase 0.5 resolved + Phase 15 stable | Per the cutover plan's own validation steps — outside ETL-3's own scope | Not started, blocked on Phase 0.5 |

**Ordering notes:**
- Phases 3 and 4 are independent of each other and can be built in parallel — V1 and V2 ingestion share no code path by design.
- Phase 11 (gap ledger) has no dependency on the current-state phases (5–8) and can be done any time after Phase 1 — it's pure copy-forward from existing source ledgers.
- Phase 10 (identity linking) depends only on Phase 6 (persons), not on accused/arrests/etc. — it can run well before Phase 8 completes.
- No phase before 16 touches DOPAMS BE or requires it to exist; Phase 0.5 is a prerequisite investigation, not an ETL-3 build task, and can happen in parallel with Phases 1–15.
